# v0.2.0-beta3: notifications bell — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stored, per-organization notifications for newly detected domains and DKIM selectors. A bell in the shell shows a red dot while any are open; each notification links to where it gets handled, and clears itself once handled.

**Architecture:**
- **Producer:** a singleton worker job `notifications_refresh` (every 10 minutes, platform-admin context, all organizations) inserts new notifications (ON CONFLICT DO NOTHING on org + kind + subject) and resolves handled ones.
- **Sources:** the same detected-domains logic as `GET /dmarc/detected-domains`, and one grouped DKIM-selector query per organization (resurrected from reverted commit 8eae9ff, extended with the signing source IP).
- **Links:** worked out when read, so a selector notification moves from "review the sender" to "add the selector" as soon as the sender is approved.

**Tech Stack:** FastAPI, SQLAlchemy async, Alembic, Postgres RLS; React/TS + TanStack Query + vitest.

**Spec:** `docs/superpowers/specs/2026-10-02-v0.2.0-design.md` §2

## Global Constraints

- Branch `v0.2.0-beta`; commit trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; no new dependencies.
- Everyone in the organization sees the bell. Only org admins can dismiss (403 otherwise).
- Selector source window: **30 days**, aligned DKIM only, not already monitored (same rule as `GET /domains/{id}/selectors/detected`).
- Resolution reasons:
  - `handled`: the domain was added or dismissed, the selector is monitored, or the signing sender was **blocked** (a rejected sender's selector isn't worth adding);
  - `dismissed`: dismissed by an admin.
- Links:
  - **domain detected:** `/settings/domains`;
  - **selector, signing sender not approved:** `/domains/{id}/senders?highlight=<label>`;
  - **selector, sender approved:** `/domains/{id}/dns?open=dkim-selectors`.
- Same test commands as plan 2.
