# v0.2.0-beta4: Ask AI — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An opt-in, per-organization "Ask AI" button that turns one issue into a ready-made prompt, previewed before it opens in Claude or ChatGPT (or is copied for Gemini and others).

**Architecture:**
- `organizations.ask_ai_enabled` (default off), set in Settings → General and in a new onboarding step.
- The backend builds every prompt (`app/services/ask_ai/prompts.py`), so what may be shared lives in one tested place.
- Action queue items carry an optional `ask_ai` hint (`kind` + `subject`) set by the rule that made them; the DNS tab and sender rows supply their own hint.
- The frontend shows one dialog: prompt preview plus provider buttons.

**Tech Stack:** FastAPI, SQLAlchemy async, Alembic; React/TS, TanStack Query, vitest.

**Spec:** `docs/superpowers/specs/2026-10-02-v0.2.0-design.md` §3

## Global Constraints

- Branch `v0.2.0-beta`; commit trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; no new dependencies.
- **Off by default.** `GET /api/ask-ai/prompt` returns 404 while the organization hasn't turned it on; the buttons only render when it's on.
- **Never in a prompt:** organization name, user emails, mailbox or reporting addresses, raw reports. Enforced at the end of the builder: every email address is replaced with `<your reporting address>` (DMARC/TLS-RPT `rua=` values and DNS-check summaries contain them). Domain names, public DNS records, sender names and IPs are fine.
- Prompts are capped at **6,000 characters** (cut at a section boundary, with a note).
- Provider links:
  - Claude: `https://claude.ai/new?q=`
  - ChatGPT: `https://chatgpt.com/?q=`
  - Gemini (copy, then open): `https://gemini.google.com/app`
  - Copy prompt.
- Frontend tests run with `--maxWorkers=1` (small host).

### Task 2: Prompt builders

**Files:**
- Create:
  - `services/ask_ai/prompts.py`
  - `services/ask_ai/__init__.py`
- Repo: `auth_domains_for_ips(db, domain_id, ips, since)` → `(spf_domains: Counter, dkim_domains: Counter)` from `auth_results` (ORM, unverified reports excluded).
- Test: `tests/services/test_ask_ai_prompts.py`

**Interfaces:**
- `async def build_prompt(db, domain, kind, subject) -> str`; raises `ValueError` for an unknown kind or subject.
- **`dns_check`** (subject = check type, e.g. `spf`):
  - domain;
  - the domain's mail profile;
  - every latest finding of that type (status + summary + `details["recommendation"]` when present);
  - the current record from DNS: `v=spf1` TXT at the domain for spf, `_dmarc` for dmarc, `_smtp._tls` for tls_rpt, `_mta-sts` for mta_sts.
- **`sender`** (subject = service label):
  - from `service_breakdown` over the organization's rating window: volume, DMARC pass %, SPF/DKIM aligned %, disposition counts, and up to 10 IPs with PTR;
  - SPF and DKIM domains seen for those IPs;
  - the domain's current SPF and DMARC records.
- **`compliance`** (subject ignored):
  - pass rate and volume over the rating window;
  - current policy;
  - the trend line when stored;
  - the 3 senders failing the most (by estimated failed messages) with their numbers.
- Every prompt opens with a fixed instruction: "I run DMARC monitoring for my domain. Help me fix the issue below. Explain the likely cause, then give step-by-step fixes with exact DNS records where relevant. Ask if you need more information." It ends with "Data from my DMARC aggregate reports and DNS."
- `redact(text)` replaces email addresses; `cap(text)` keeps it at 6,000 characters or fewer.

- [ ] **Failing tests:**
  - each kind contains its key facts;
  - none contain the organization name, a seeded user email, a `rua=mailto:` address, or the mailbox address (seeded so they'd otherwise appear: the DMARC record and a DNS summary containing the address);
  - an oversized prompt is capped.
- [ ] Implement, commit.

### Task 3: API and Action queue hints

**Files:**
- Create: `routers/ask_ai.py` (`GET /api/ask-ai/prompt?kind=&domain_id=&subject=`)
- Register it in `main.py`.
- Modify:
  - `services/action_queue/rules.py` (`ActionItem.ask_ai: dict | None`)
  - `routers/action_queue.py` (merge keeps the lead item's hint)

**Hints per rule:**

| Rule | `ask_ai` |
|---|---|
| sender items (unreviewed, likely spoofed, alignment, failing with a named sender) | `{"kind": "sender", "subject": label}` |
| `low_compliance_domain` | `{"kind": "dns_check", "subject": <worst factor's check type>}` when it has one, else `compliance` |
| `spf_lookup_limit_risk` | `dns_check` / `spf` |
| `rua_destination_broken`, `parked_domain_not_locked_down` | `dns_check` / `dmarc` |
| readiness ("ready" and "not ready"), `trending_down`, failing without a named sender | `compliance` |
| `mailbox_stopped_receiving_reports` | none |
