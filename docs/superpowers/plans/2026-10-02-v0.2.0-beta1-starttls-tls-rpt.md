# v0.2.0-beta1: STARTTLS from TLS-RPT reports — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the STARTTLS check take its result from TLS-RPT reports instead of a port-25 probe, so it works on Azure, with a `pending` state for "set up but no reports yet".

**Architecture:** A `STARTTLS_CHECK_MODE` setting (`probe` / `tls_rpt` / `off`) decides the source. `probe` stays in `registry.run_all` (no DB). `tls_rpt` runs in `run_and_persist_checks`, which has a DB session: a pure evaluator turns the domain's last 14 days of TLS-RPT summary counts plus the rua= destination status into findings. A new `pending` CheckStatus is ignored by scoring.

**Tech Stack:** FastAPI, SQLAlchemy async, Alembic, Postgres; React/TS + vitest; Bicep.

**Spec:** `docs/superpowers/specs/2026-10-02-v0.2.0-design.md` §4

## Global Constraints

- Branch `v0.2.0-beta`. Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- No new dependencies.
- `STARTTLS_CHECK_ENABLED=false` must keep meaning "off" (existing Azure deployments set it).
- Existing Azure parameter files pass `enableStarttlsCheck`; the template must still accept it.
- Thresholds (verbatim from the spec): last **14 days**; `pass` when successes > 0 and failures ≤ **2%** of all sessions; `warn` above 2%; `fail` when failures > 0 and successes = 0.
- A domain whose TLS-RPT rua= doesn't reach its hosted address or the org mailbox gets **no** STARTTLS finding in `tls_rpt` mode (the TLS-RPT check already warns about the record).
- Backend tests: `TEST_DATABASE_URL=postgresql+asyncpg://postgres:postgres@localhost:55432/dmarc_test PYTHONDONTWRITEBYTECODE=1 python3 -m pytest -q -p no:cacheprovider` from `backend/`. Frontend: `npx tsc -b && npx vitest run` from `frontend/`.

```python
"""STARTTLS result from TLS-RPT reports (STARTTLS_CHECK_MODE=tls_rpt): what
real senders (Google, Microsoft, ...) report about TLS to this domain's MX
hosts, for hosts that can't probe port 25 themselves (Azure blocks it).
Summary counts are per policy domain; failure details name the MX host."""

from datetime import datetime, timedelta, timezone

from sqlalchemy.ext.asyncio import AsyncSession

from app.repositories.dmarc_reports import tls_rpt_session_totals_for_domain
from app.services.dns_checks.base import Finding
from app.services.dns_checks.tls_rpt_check import check_tls_rpt_rua_destination

WINDOW_DAYS = 14
MAX_FAILURE_RATE = 0.02


def _failure_summary(failure_details: list[dict]) -> str:
    by_host: dict[str, dict[str, int]] = {}
    for item in failure_details:
        host = item.get("receiving_mx_hostname") or "unknown host"
        kind = item.get("result_type") or "unknown"
        by_host.setdefault(host, {})
        by_host[host][kind] = by_host[host].get(kind, 0) + int(item.get("failed_session_count") or 0)
    return "; ".join(
        f"{host}: " + ", ".join(f"{kind} ({count})" for kind, count in sorted(kinds.items(), key=lambda kv: -kv[1]))
        for host, kinds in sorted(by_host.items())
    )


def evaluate(rua_status: str, success: int, failure: int, failure_details: list[dict]) -> list[Finding]:
    if rua_status != "correct":
        return []  # TLS-RPT doesn't reach this app: no result, the TLS-RPT check says why
    total = success + failure
    if total == 0:
        return [Finding(status="pending", summary=f"Waiting for TLS-RPT reports (none in the last {WINDOW_DAYS} days)")]
    details = {"successful_sessions": success, "failed_sessions": failure, "window_days": WINDOW_DAYS, "source": "tls_rpt"}
    if success == 0:
        return [Finding(status="fail", summary=f"No TLS session succeeded in {failure:,} reported: {_failure_summary(failure_details)}", details=details)]
    if failure / total > MAX_FAILURE_RATE:
        return [Finding(status="warn", summary=f"{failure:,} of {total:,} reported TLS sessions failed: {_failure_summary(failure_details)}", details=details)]
    return [Finding(status="pass", summary=f"{success:,} of {total:,} reported TLS sessions succeeded in the last {WINDOW_DAYS} days", details=details)]


async def check(db: AsyncSession, domain_id, domain_name: str, mailbox_address: str | None) -> list[Finding]:
    rua_status = "no_mailbox" if not mailbox_address else (await check_tls_rpt_rua_destination(domain_name, mailbox_address)).status
    if rua_status != "correct":
        return []
    since = datetime.now(timezone.utc) - timedelta(days=WINDOW_DAYS)
    success, failure, failure_details = await tls_rpt_session_totals_for_domain(db, domain_id, since)
    return evaluate(rua_status, success, failure, failure_details)
```

Repository function (ORM, so the unverified-report filter applies):

```python
async def tls_rpt_session_totals_for_domain(db: AsyncSession, domain_id: UUID, since: datetime) -> tuple[int, int, list[dict]]:
    rows = (
        await db.execute(
            select(TlsRptReport.summary_success_count, TlsRptReport.summary_failure_count, TlsRptReport.failure_details).where(
                TlsRptReport.domain_id == domain_id, TlsRptReport.date_range_begin >= since
            )
        )
    ).all()
    details = [item for _s, _f, fd in rows for item in (fd or [])]
    return sum(r[0] for r in rows), sum(r[1] for r in rows), details
```
