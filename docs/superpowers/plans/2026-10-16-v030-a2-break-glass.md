# v0.3.0 part A2: break-glass account, org-chosen sign-in provider — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Every organization has one local break-glass account; only that account can choose or switch the organization's sign-in provider (Microsoft, Google Workspace or OIDC), each proven by a test sign-in; sign-in links become random and rate-limited; the Microsoft mailbox keeps its own tenant so sign-in can change without breaking report ingestion.

**Spec:** `docs/superpowers/specs/2026-10-16-v030-sign-in-and-report-sources-design.md` (section A), amended by the decisions below (2026-10-16, user).

## Decisions (user, 2026-10-16)

- One **break-glass** account per organization: local (password + authenticator), org admin. The platform admin creates it with a new organization; existing organizations get one from the platform admin ("Create break-glass account").
- Organizations **without** a provider may still add local teammates. Once an organization has a provider, only the break-glass account stays local: other local accounts are disabled on the switch (the platform admin can help), and no new local teammates can be added.
- **Only a session of the break-glass account** can choose, switch or remove the provider. Every provider (Microsoft, Google, OIDC) is saved only after a test sign-in; the tenant ID / Workspace domain comes from the provider's signed token, and the test account's email must be on one of the organization's verified domains. Switching ends all sessions of non-local users of that organization.
- Org admins (also those signed in through the provider) may reset the break-glass account's password or authenticator.
- The platform admin can always help with a lockout: create a break-glass account, reset it, make another local account the break-glass account, and set the provider directly (no test).
- "Expected admin" is no longer asked for when creating an organization; provider users start as members and the break-glass account promotes them. Existing `expected_admin_email` values keep working.
- Sign-in link names are random by default (10 lowercase letters/digits); the platform admin may set a readable one. All existing organizations get a random one (beta only; no links were shared). `/api/auth/org/{slug}` and `/api/auth/oidc/start` are rate-limited like the password login.
- `mailbox_connections.ms_tenant_id`: the Microsoft 365 mailbox's own tenant (copied from the organization on migration and when connecting); polling and resync use it.

## Global Constraints

Same as part A's plan (`2026-10-16-v030-a-sign-in-providers.md`): no new dependencies, private-address guard for OIDC issuers, verified domains only, secrets encrypted and never returned, no SAML mentions, commit attribution, test commands, never two heavy suites at once.
